================================================================================
Aeronit Defence Website - Hosting Deployment Guide
================================================================================

This is a React Single Page Application (SPA) built with Vite.
The built files are in the "dist/" folder.

--------------------------------------------------------------------------------
QUICK DEPLOYMENT INSTRUCTIONS
--------------------------------------------------------------------------------

1. BUILD THE PROJECT:
   cd frontend
   npm run build
   
   This creates the "dist/" folder with all static files.

2. UPLOAD THE "dist/" FOLDER CONTENT to your hosting platform.

--------------------------------------------------------------------------------
HOSTING PLATFORM SPECIFIC INSTRUCTIONS
--------------------------------------------------------------------------------

[A] NETLIFY (Easiest - Drag & Drop or Git Integration)
--------------------------------------------------------------------------------
Option 1 - Drag & Drop:
   - Go to https://app.netlify.com/sites/new
   - Drag and drop the "dist/" folder
   - Netlify will auto-detect the netlify.toml file
   
Option 2 - Git Integration:
   - Connect your GitHub repo
   - Build command: npm run build
   - Publish directory: dist
   - The netlify.toml handles SPA routing automatically

[B] VERCEL (Recommended for React apps)
--------------------------------------------------------------------------------
   - Go to https://vercel.com
   - Connect your GitHub repo
   - Vercel auto-detects Vite/React
   - The vercel.json handles SPA routing
   - Or use CLI: npm i -g vercel && vercel --prod

[C] GITHUB PAGES
--------------------------------------------------------------------------------
   - Update vite.config.js: set base: '/repo-name/'
   - Build: npm run build
   - Push dist/ to gh-pages branch using gh-pages package
   - Note: GitHub Pages doesn't need extra routing config for root path
   
   For subdirectory deployment, add to vite.config.js:
   export default defineConfig({
     base: '/your-repo-name/',
     // ... rest of config
   })

[D] CUSTOM HOSTING (cPanel, Shared Hosting, etc.)
--------------------------------------------------------------------------------
   - Upload all files from "dist/" to your public_html or www folder
   - Add the following to .htaccess (Apache) for SPA routing:
   
   RewriteEngine On
   RewriteBase /
   RewriteRule ^index\.html$ - [L]
   RewriteCond %{REQUEST_FILENAME} !-f
   RewriteCond %{REQUEST_FILENAME} !-d
   RewriteRule . /index.html [L]
   
   - For Nginx, add to server block:
   location / {
       try_files $uri $uri/ /index.html;
   }

[E] AMAZON S3 + CLOUDFRONT
--------------------------------------------------------------------------------
   - Upload dist/ contents to S3 bucket
   - Enable static website hosting
   - Set index document: index.html
   - Set error document: index.html (for SPA routing)
   - CloudFront will handle caching

--------------------------------------------------------------------------------
IMPORTANT NOTES FOR SPA ROUTING
--------------------------------------------------------------------------------

The refresh/routing issue you mentioned is NORMAL for SPAs on some hosts.

WHY IT HAPPENS:
- React Router handles navigation client-side (no server request)
- When you directly visit /about or refresh on /about, the server 
  tries to find an "about" folder/file which doesn't exist
- Solution: Configure server to return index.html for all routes

FILES ADDED FOR ROUTING:
- _redirects (Netlify)
- 404.html (Fallback redirect)
- vercel.json (Vercel)
- netlify.toml (Netlify)

These files tell the hosting server to serve index.html for any route,
allowing React Router to handle the routing client-side.

--------------------------------------------------------------------------------
VERIFICATION AFTER DEPLOY
--------------------------------------------------------------------------------

1. Visit your deployed site
2. Navigate to different pages using the menu links
3. Refresh the page on each route - should work without 404
4. Try direct URL access like /about, /contact, /capabilities

If any page shows 404, check your hosting platform's SPA routing settings.

--------------------------------------------------------------------------------
ENVIRONMENT VARIABLES (If needed)
--------------------------------------------------------------------------------

If your backend API is on a different domain, set:
VITE_API_BASE = https://your-api-domain.com

In Vite, environment variables must start with VITE_ to be exposed to 
the frontend. Add to .env file or set in hosting platform's environment 
variables section.
